# 2. Khóa lịch một chỗ

Lỗ chết người của SRS v1.2 DDL: exclusion tách trên sessions và court_bookings — lớp vẫn đè sân. SDD sửa: một bảng occupancies là nguồn sự thật. Session, booking, hold, bảo trì, convert chỉ được tồn tại nếu INSERT occupancy thành công trong cùng transaction.

*[Sơ đồ: occupancy]*

1. Cấm ghi occupancies trực tiếp. Chỉ function occupancy_attach / confirm_hold / release / attach_convert.
2. Exclusion trên mọi hàng đang tồn tại — terminal state PHẢI release (xóa hàng) nếu không slot chết.
3. hold→confirmed: occupancy_confirm_hold (đổi kind, cùng id). Cấm attach hàng thứ hai.
4. Booking occupying ⇒ occupancy_id NOT NULL UNIQUE. Terminal ⇒ NULL sau release.
5. Không bảng court_blocks. Bảo trì = attach kind=maintenance.
6. Convert: occupancy_attach_convert = đúng 2 hàng (sân + pair_court_id) cùng convert_group_id.
7. HLV chính + phụ: mỗi người một coach_occupancies (FK session).
8. UUID booking/session sinh trước, attach occupancy với ref_id đó, rồi INSERT nghiệp vụ kèm occupancy_id.

> **Cấm**
> Cấm ‘kiểm tra trống rồi insert’ không qua occupancies. Cấm SERIALIZABLE như biện pháp thay exclusion. Cấm dual-write occupancy sau khi đã commit booking.

# 4. API Must

Danh mục endpoint tab API. Không path lạ. Prefix /v1. JSON. Lỗi { code, message, br? }. Idempotency-Key bắt buộc trên POST bookings, confirm, payments, walk-in.

### 4.1 Biên giao dịch confirm sân

1. BEGIN
2. SELECT booking FOR UPDATE WHERE status=hold AND hold_until > now()
3. Tính số phải thu theo 4.2 (BR-43A) rồi ghi payment/invoice hoặc trừ quota
4. UPDATE occupancy.kind hold → booking (cùng hàng)
5. UPDATE booking confirmed + snapshot price_vnd / discount_pct / vat_rate (BR-39D, BR-42)
6. COMMIT — fail bất kỳ → ROLLBACK, hold còn đến TTL

### 4.2 Tính tiền sân (BR-34, BR-34A, BR-34B, BR-42A, BR-43, BR-43A)

1. Giá niêm yết: price_rules khớp sport + day_kind + khung giờ; rule có court_id thắng rule chung. Không khớp → `BR_VIOLATION { br: 'BR-34B' }`, cấm giá mặc định.
2. % giảm: chỉ khi user có subscription status=active AND start_on ≤ today ≤ end_on đúng môn hoặc all (BR-19A, BR-34). Ngoài biên 0–100 → `BR_VIOLATION { br: 'BR-34A' }`, không kẹp.
3. VAT: `prices_include_vat = true` → số phải thu = giá sau giảm, hóa đơn tách “trong đó VAT”. `false` → cộng `vat_rate` (BR-42A).
4. Làm tròn **một lần** tới `round_vnd`, nửa lên (BR-43). Không làm tròn bước trung gian, không làm tròn lại khi in.
5. Khuyến mại / quota (BR-46, BR-17), rồi snapshot (BR-39D).

POST /bookings (ghi price_vnd lúc hold) và confirm dùng cùng hàm tính, nên số hiển thị = số thu (BR-42A).

### 4.3 Tạo / thay hold (BR-39, BR-39H)

1. BEGIN
2. Kiểm tra toàn bộ hold mới: sân ready + không bảo trì (BR-36), trong giờ mở (BR-35), slot 60’ giờ chẵn (BR-30), cửa sổ đặt (BR-32), không quá khứ (BR-66), có bảng giá (BR-34B), chồng lớp của user (BR-39C), slot trống — SELECT occupancies giao [start, end) trên sân, bỏ qua hold cũ của chính user (BR-21). Lỗi → `BR_VIOLATION` / CONFLICT_SLOT, ROLLBACK, hold cũ không đổi.
3. `booking_replace_hold(...)`: khóa hold cũ FOR UPDATE, release, attach hold mới. Exclusion vẫn là chốt chặn race: người khác vừa chiếm slot → CONFLICT_SLOT (BR-21), ROLLBACK khôi phục hold cũ.
4. INSERT court_bookings status=hold, price_vnd theo mục 4.2, hold_until = now() + hold_minutes.
5. COMMIT. Chỉ tới đây hold cũ mới thực sự mất; mọi lỗi trước đó để hold cũ và `hold_until` nguyên vẹn.

Phiên: token opaque (hash trên DB). TV 7 ngày, nhân sự 12 giờ. Cookie httpOnly hoặc Bearer — chọn một, không mix. OTP 6 số TTL 5 phút, khóa 5 lần/15 phút.

# Occupancy rules
- Backend CHỈ connect role arena3_app. REVOKE INSERT/UPDATE/DELETE occupancies — chỉ EXECUTE occupancy_* + booking_replace_hold.
- Hold mới: kiểm tra BR của hold mới trước, rồi booking_replace_hold — hủy hold cũ cùng TX (TC-16). Lỗi → ROLLBACK, hold cũ giữ nguyên hold_until (BR-39H, TC-45). Cấm occupancy_attach hold trực tiếp từ API.
- Hủy / no-show / completed: occupancy_release_booking (NULL occupancy_id rồi DELETE).
- Job complete_bookings: in_use AND end_at+ân hạn < now() → occupancy_release_booking(..., completed).
- Convert: attach_convert; exception xóa convert_group rồi CONFLICT_SLOT.
- Session UNIQUE (class_id, start_at). Generate conflict = skip.
- Một ca open / lễ tân (one_open_shift).
- Phone lưu E.164 qua normalize_phone. member_code = next_member_code().
- Giá holiday: seed copy weekend; lookup đúng day_kind, không fallback. Không có rule → BR-34B.
- Notify: chỉ outbox. inbox = view sent inapp. Cấm bảng notifications.

# Confirm transaction
1. BEGIN
2. Khóa hàng booking status=hold AND hold_until > now() (SELECT FOR UPDATE)
3. Tính tiền theo mục 4.2 (BR-43A). Ghi payment: tiền → posted; quota → method=quota amount_vnd=0 status=posted (không cộng DT)
4. occupancy_confirm_hold(booking.occupancy_id)
5. UPDATE booking SET status='confirmed', snapshot price_vnd / discount_pct / vat_rate
6. COMMIT
7. Fail bất kỳ bước → ROLLBACK, hold còn nguyên đến TTL

## expire_holds (every 15s, slice 1)
- SELECT hold hết hạn FOR UPDATE.
- occupancy_release_booking(id, 'cancelled') — NULL occupancy_id rồi DELETE occupancy.
- Idempotent: UPDATE bookings hold WHERE hold_until < now() — chạy lại không double-delete.

## mark_noshow (every 1m, slice 1)
- Booking confirmed AND start_at + noshow_grace < now() AND chưa check-in.
- occupancy_release_booking(id, 'no_show'). Không hoàn.
- Idempotent: Chỉ đụng status=confirmed.

## complete_bookings (every 1m, slice 1)
- in_use AND end_at + ân hạn (settings) < now().
- occupancy_release_booking(id, 'completed').
- Idempotent: Chỉ status=in_use.

## subscription_status (0 0 * * *, slice 1)
- frozen giữ nguyên.
- status=active AND end_on < today → expired.
- Không đụng gói Scheduled (active AND start_on > today); nó tự mở quyền lợi khi tới start_on (BR-19A).
- Không set expiring. API danh sách ‘sắp hết hạn’ = active AND end_on <= today+7.
- Idempotent: Chỉ active|frozen. expired suy từ end_on. Không ghi status=expiring.

## expiry_reminders (0 8 * * *, slice 1)
- Mốc 7, 3, 0 ngày (settings). In-app bắt buộc. SMS nếu flag.
- Idempotent: Một notification/user/mốc/ngày (unique key).

## generate_sessions (0 1 * * *, slice 1)
- Với class open, rrule subset RFC5545 FREQ=WEEKLY;BYDAY;BYHOUR + duration_min → 14 ngày tới.
- UUID session trước → occupancy_attach kind=session đúng start+duration (90’ không làm tròn 60’).
- Conflict sân/HLV → không tạo, outbox Manager.
- Idempotent: Không tạo session nếu đã có class_id+start_at.

## waitlist_expire (every 1m, slice 2)
- Hết hạn mời → skipped; tạo offer mới cho enrollment kế.
- Idempotent: Offer pending quá expires_at → expired, mời pos+1.

## lock_attendance (every 10m, slice 2)
- status=done; cấm HLV sửa.
- Idempotent: Session done khi end_at+2h.

## notify_flush (every 10s, slice 1)
- SELECT outbox WHERE sent_at IS NULL.
- Gửi in-app / SMS stub.
- SET sent_at. attempts < 5.
- sub_expiring: dedupe_key = {user_id}|{mốc}|{YYYY-MM-DD}.
- Idempotent: outbox.dedupe_key UNIQUE; chỉ sent_at IS NULL.

# State machines
## Subscription
- pending → active : thanh toán đủ (hoặc cọc BR-45)
- active → expired : job nightly khi end_on < today
- expired → active : gia hạn BR-11
- active → active : gia hạn BR-10 (đổi end_on)
- active → frozen : Manager
- frozen → active : hết freeze / Manager
Không có status expiring hay scheduled. UI lọc active AND end_on≤today+7; Scheduled = active AND start_on > today, chưa mở quyền lợi (BR-19A). Frozen không bị job đè. Cửa sổ ngày (user, sport_scope) không giao nhau với active|frozen.

## CourtBooking + occupancy.kind
- hold → confirmed : confirm + pay/quota
- hold → cancelled : hết TTL / user hủy / thay bằng hold mới hợp lệ (BR-39H)
- confirmed → cancelled : hủy ≥ 2h + hoàn
- confirmed → in_use : check-in cửa sổ
- confirmed → no_show : +10 phút
- in_use → completed : hết slot + ân hạn
Không nhảy ngược. Confirm fail giữ hold.

## Enrollment
- → confirmed : còn chỗ + BR
- → waitlisted : đầy (slice 2)
- waitlisted → confirmed : nhận offer
- waitlisted → cancelled : hết hạn offer / bỏ
- confirmed → cancelled : hủy ≥ 4h (trả chỗ)
Slice 1 chỉ confirmed|cancelled.

## Payment
- → posted : thu / quota 0đ / hoàn < 1tr
- → refund_pending : lễ tân hoàn ≥ 1tr
- refund_pending → posted : Manager duyệt
- refund_pending → refund_rejected : Manager từ chối — cấm DELETE
Không DELETE. TC-22.

CREATE OR REPLACE FUNCTION occupancy_attach(
  p_court UUID, p_start TIMESTAMPTZ, p_end TIMESTAMPTZ,
  p_kind occ_kind, p_ref UUID, p_reason TEXT DEFAULT NULL
) RETURNS UUID LANGUAGE plpgsql AS $$
DECLARE v_id UUID;
BEGIN
  INSERT INTO occupancies (court_id, start_at, end_at, kind, ref_id, reason)
  VALUES (p_court, p_start, p_end, p_kind, p_ref, p_reason)
  RETURNING id INTO v_id;
  RETURN v_id;
EXCEPTION WHEN exclusion_violation THEN
  RAISE EXCEPTION 'CONFLICT_SLOT' USING ERRCODE = '23P01';
END $$;

CREATE OR REPLACE FUNCTION occupancy_confirm_hold(p_id UUID) RETURNS VOID LANGUAGE plpgsql AS $$
BEGIN
  UPDATE occupancies SET kind = 'booking' WHERE id = p_id AND kind = 'hold';
  IF NOT FOUND THEN
    RAISE EXCEPTION 'HOLD_EXPIRED_OR_BAD_KIND';
  END IF;
END $$;

-- Job/hủy: NULL occupancy_id TRƯỚC, rồi DELETE occupancy (tránh FK chặn)
CREATE OR REPLACE FUNCTION occupancy_release_booking(p_booking UUID, p_terminal booking_status)
RETURNS VOID LANGUAGE plpgsql AS $$
DECLARE v_occ UUID;
BEGIN
  IF p_terminal NOT IN ('cancelled','no_show','completed') THEN
    RAISE EXCEPTION 'BAD_TERMINAL';
  END IF;
  SELECT occupancy_id INTO v_occ FROM court_bookings WHERE id = p_booking FOR UPDATE;
  UPDATE court_bookings SET occupancy_id = NULL, status = p_terminal WHERE id = p_booking;
  IF v_occ IS NOT NULL THEN
    DELETE FROM occupancies WHERE id = v_occ;
  END IF;
END $$;

CREATE OR REPLACE FUNCTION occupancy_release_session(p_session UUID, p_terminal session_status)
RETURNS VOID LANGUAGE plpgsql AS $$
DECLARE v_occ UUID;
BEGIN
  IF p_terminal NOT IN ('done','cancelled') THEN
    RAISE EXCEPTION 'BAD_TERMINAL';
  END IF;
  SELECT occupancy_id INTO v_occ FROM sessions WHERE id = p_session FOR UPDATE;
  UPDATE sessions SET occupancy_id = NULL, status = p_terminal WHERE id = p_session;
  IF v_occ IS NOT NULL THEN
    DELETE FROM occupancies WHERE id = v_occ;
  END IF;
  DELETE FROM coach_occupancies WHERE session_id = p_session;
END $$;

CREATE OR REPLACE FUNCTION occupancy_release_convert(p_group UUID) RETURNS VOID LANGUAGE plpgsql AS $$
BEGIN
  DELETE FROM occupancies WHERE convert_group_id = p_group;
END $$;

DECLARE v_pair UUID; v_group UUID := gen_random_uuid(); v_id UUID;
BEGIN
  SELECT pair_court_id INTO v_pair FROM courts WHERE id = p_court;
  IF v_pair IS NULL THEN
    RAISE EXCEPTION 'COURT_NOT_CONVERTIBLE';
  END IF;
  INSERT INTO occupancies (court_id, start_at, end_at, kind, ref_id, convert_group_id)
  VALUES (p_court, p_start, p_end, 'convert', p_ref, v_group)
  RETURNING id INTO v_id;
  INSERT INTO occupancies (court_id, start_at, end_at, kind, ref_id, convert_group_id)
  VALUES (v_pair, p_start, p_end, 'convert', p_ref, v_group);

-- BR-39H: caller PHẢI kiểm tra BR-21/30/32/34B/35/36/39C/66 của hold mới TRƯỚC khi gọi, trong cùng transaction (mục 4.3).
-- Release hold cũ trước attach vì one_hold_per_user là unique index. Attach đụng lịch (BR-21)
-- hay lỗi sau đó → ROLLBACK cả transaction → hold cũ và hold_until khôi phục nguyên vẹn.
CREATE OR REPLACE FUNCTION booking_replace_hold(
  p_user UUID, p_phone VARCHAR, p_court UUID,
  p_start TIMESTAMPTZ, p_end TIMESTAMPTZ, p_booking UUID
) RETURNS UUID LANGUAGE plpgsql AS $$
DECLARE v_old UUID;
BEGIN
  SELECT id INTO v_old FROM court_bookings
  WHERE status = 'hold'
    AND (
      (p_user IS NOT NULL AND user_id = p_user)
      OR (p_phone IS NOT NULL AND guest_phone = p_phone)
    )
  FOR UPDATE;
  IF v_old IS NOT NULL THEN
    PERFORM occupancy_release_booking(v_old, 'cancelled');
  END IF;
  RETURN occupancy_attach(p_court, p_start, p_end, 'hold', p_booking, NULL);
END $$;

CREATE OR REPLACE FUNCTION normalize_phone(p TEXT) RETURNS VARCHAR
LANGUAGE sql IMMUTABLE AS $$
  SELECT CASE
    WHEN p ~ '^\+84' THEN p
    WHEN p ~ '^84' THEN '+' || p
    WHEN p ~ '^0' THEN '+84' || substr(p, 2)
    ELSE p
  END
$$;

CREATE OR REPLACE FUNCTION next_member_code() RETURNS VARCHAR
LANGUAGE plpgsql AS $$
DECLARE y INT := EXTRACT(YEAR FROM (now() AT TIME ZONE 'Asia/Ho_Chi_Minh'));
DECLARE n INT;
BEGIN
  INSERT INTO code_counters(kind, yyyy, n) VALUES ('member', y, 1)
  ON CONFLICT (kind, yyyy) DO UPDATE SET n = code_counters.n + 1
  RETURNING n INTO n;
  RETURN 'A3-' || y::text || '-' || lpad(n::text, 4, '0');
END $$;

CREATE OR REPLACE FUNCTION enrollment_confirm(p_class UUID, p_user UUID) RETURNS UUID
LANGUAGE plpgsql AS $$
DECLARE v_id UUID;
BEGIN
  PERFORM 1 FROM classes WHERE id = p_class FOR UPDATE;
  IF EXISTS (
    SELECT 1 FROM enrollments WHERE class_id = p_class AND user_id = p_user AND status = 'confirmed'
  ) THEN
    RAISE EXCEPTION 'ALREADY_ENROLLED';
  END IF;
  UPDATE classes SET enrolled_count = enrolled_count + 1
  WHERE id = p_class AND enrolled_count < capacity AND status = 'open';
  IF NOT FOUND THEN
    RAISE EXCEPTION 'CLASS_FULL';
  END IF;
  INSERT INTO enrollments (class_id, user_id, status)
  VALUES (p_class, p_user, 'confirmed')
  ON CONFLICT (class_id, user_id) DO NOTHING
  RETURNING id INTO v_id;
  IF v_id IS NULL THEN
    UPDATE classes SET enrolled_count = enrolled_count - 1 WHERE id = p_class;
    RAISE EXCEPTION 'ALREADY_ENROLLED';
  END IF;
  RETURN v_id;
END $$;
